От свечи Bitfinex до прогноза MLP

Один сигнал даёт один пример. X описывает рынок к моменту сигнала. y обозначает класс, рассчитанный по результату сделки после комиссии.

Что сохраняет сборщик

Закрытые свечи M1, M5, M15 и M30 → сборщик Bitfinex

Сборщик рассчитывает признаки, отмечает сигналы основных якорей и по последующим свечам моделирует результат сделки для каждого сигнала.

Общие данные для обоих режимов

Рынок по минутам · feature_timeline.npy
Одна строка на минуту. В ней 36 числовых признаков и 18 флагов основных якорей.

Сигналы и их результаты · entry_targets.csv
Одна строка на сигнал. В ней ID, время, номер строки в минутной шкале, результат сделки, исполнения, комиссия и время готовности результата.

Описание формата · manifest.json
Задаёт порядок признаков, начало шкалы, длину окна и ставки комиссий.

Сохранить готовые выборки

Обычный запуск. К трём общим файлам сборщик добавляет четыре массива.

X_train.npy и y_train.npy — окна и ответы обучающей части.

X_test.npy и y_test.npy — окна и ответы тестовой части.

Строка с номером i в X соответствует ответу с номером i в y той же части.

Сохранить общие данные

Параметр команды --timeline-only. Сборщик сохраняет три общих файла. Загрузчик MLP собирает из них окна по мере чтения.

Эти три файла есть и при обычном запуске. Для MLP подходят оба варианта экспорта.

Как MLP использует общие данные

Сигнал → строка шкалы → вход X

entry_id связывает результат с сигналом. feature_end_row указывает последнюю минуту его окна. Загрузчик берёт 1 409 предыдущих минут и минуту сигнала, в порядке от старой к новой.

В примере для entry_id = 3 история занимает строки 50…1458, текущая минута — строку 1459. Окно 1 410 × 54 даёт 76 140 чисел на вход модели.

Обучение по завершённым исходам

Доходность и комиссия → ответ y. В примере 0,216516% − 0,30% = −0,083484%, поэтому y = 0.

Примеры (X, y) → разделение по времени → обучение на train → выбор модели на validation → итоговая оценка на test.

best.pt — выбранная модель.
test_metrics.json — итоговая оценка.

Прогноз для нового сигнала

Минутная шкала + описание формата + список сигналов дают новый X. Из списка нужны ID, время сигнала и номер строки шкалы.

Новый X + сохранённая модель → predictions.csv. Для каждого сигнала записываются вероятности пропуска и входа, а также предсказанный класс.

Два различия между готовыми ответами и обучением MLP

Безубыточная исполненная сделка. При доходности, в точности равной комиссии, сборщик записывает 1, MLP присваивает 0. Для MLP класс 1 означает строгую прибыль.

Граница выборок. Сборщик начинает с 80/20 и требует, чтобы ответ обучающего примера стал известен раньше первого тестового сигнала. MLP начинает с 70/15/15 и проверяет готовность ответа до первой минуты истории следующей части. После удаления пересечений доли могут измениться.

Словарь полей и файлов

Время и строки
  • entry_at — время сигнала, когда выставляется начальный ордер. Исполнение может произойти позже.
  • feature_end_row — номер последней строки окна в общей шкале. Отсчёт начинается с нуля.
  • label_available_at — первый момент, когда известен окончательный исход. Может наступить позже выхода из сделки.
  • split и split_row — часть выборки сборщика и номер примера внутри неё. В компактном экспорте размеченные сигналы имеют значение unsplit, а номер строки пуст.
Ответ и прогноз
  • target_gross_return_pct — суммарная доходность серии до комиссии в процентах.
  • commission_pct — комиссия за исполненные входы и выходы в процентах. Значение 0,05 означает 0,05%.
  • binary_target — исторический класс по правилу сборщика. Загрузчик MLP рассчитывает свой y по доходности и комиссии.
  • p_skip и p_enter — оценки вероятности классов 0 и 1, которые выдаёт модель.
  • predicted_class — класс, выбранный моделью для сигнала. При оценке качества его сравнивают с известным y.
